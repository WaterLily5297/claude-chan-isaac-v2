Owner-requested scope, 2026-10-23. This records design targets, not completion or native acceptance. Current source has 22 forms and baseline implementations for all fifty expansion items (Summary Stapler first, rows 02-50 on 2026-10-24). Where a target differed from the implementation, the 2026-10-28 decisions (F3, F5, F14) adopted the implemented rule and the rows below now say so; see [ITEM_COMPLETION.md](ITEM_COMPLETION.md) for all 97 registered items, actual state boundaries and gaps. Preserve existing mechanics until replacements and migrations are deliberately approved; these fictional values are not claims about real model performance.

### Backlog implementation notes (rows 02-50)

Rows 02-50 live in `scripts/items/backlog/`: one module per family plus `common.lua`, a single shared service for attacks, guards, timers, helpers, labels, unique clears and saved state. Tests: `tests/backlog_items_test.lua` and `tests/backlog_more_test.lua` over the stub engine in `tests/lib/backlog_env.lua`.

- **Attacks.** A same-frame tear volley, a new laser, a knife throw or a Dr. Fetus bomb is one attack. Primed bonuses are consumed once per attack and leased to its entities for at most 120 frames, then applied when they hit by re-dealing the damage (no entity damage writes). A child laser with validated direct Parent ancestry shares the resolved parent attack identity, multiplier and original expiry without consuming another prime or emitting an attack. Unresolved children never synthesize a parent payment. Derived tears (One More Finger, Please Retry) are never attacks, primes or event sources, so nothing recurses.
- **Guards** absorb one ordinary hostile bullet each (Summary Stapler's rules: variant 0, no projectile flags, a living non-friendly NPC spawner). Special projectiles, contact, fake and no-penalty damage pass. A guarded hit counts as no hit for flawless checks.
- **Unique clears** are deduplicated per saved floor key and room grid index, and are only tracked while someone holds an item that uses them. Saved state is `Risk.state.backlog` (version 1, per player slot, floor-scoped sub-table); no entity is saved. Players without backlog items get no state.
- **Charged active uses** (Base Model, Please Come Back, Access Pass) count only owned, non-Car-Battery uses of an ordinary room-charged item whose slot actually lost charge on the next update.
- Every active ignores Car Battery's second use, and every targeted active keeps its charge without a target.
- **Deviations from the design text:** Dario's Red Stamp cancels the stamped enemy's contact before any hit event, so it never counts as a hit. One Bowl Only grants a new guard only when the previous bowl guard has been used. Tibo Reset's two pending rooms may carry into the next floor. Stand-Up Meeting recalls only Unchanged Preview decoys (the only backlog helpers). Token Recall takes the owner's blue and blood tears only, whatever their flags; special tear types stay untouched (kept (owner delegated, 2026-10-28)). Consensus Coin counts tear, laser, knife, bomb and familiar sources; contact and unknown sources never count.
- Tear-only parts: One More Finger and Please Retry fire native tears whatever the weapon. Laser, knife and bomb attacks receive primes and target modifiers, but continuous beams only within the 120-frame lease.

## Implementation and performance gates

Each item needs registration, pool, English description, original icon/provenance, tests, documentation and engine acceptance. Do not register the forty-nine designs as empty collectible shells. Use native damage/cache/weapon interfaces; do not force character sprites or overwrite another item's appearance. Weapon-independent effects must retain player/familiar ownership and handle lasers, knives and bombs explicitly. Tear-only behavior must say so.

Persistent resources live in saved per-player state with a versioned migration. Temporary tasks store remaining gameplay frames and room identity when continuation matters, never raw entity references in JSON. Exiting/re-entering, restarting, changing character and joining co-op must not refill resources or duplicate rewards. Failed/cancelled actives and Car Battery require explicit behavior. RNG is seeded and item-specific; no global random reseed on continue.

Use event-driven callbacks. Cache player ownership/state within one callback, not forever. Bounded target lists should replace repeated whole-room scans every frame. Helper budgets are shared per owner: no more than twelve simultaneous expansion helpers and no unbounded nested forks. A cap may defer an extra visual effect, but must not silently erase earned rewards. Profile before making numerical performance claims.

Roll out in small reviewable branches: character state framework, then one family or item per change. Engine checks and art acceptance remain separate from stub/CI passes. The source, GitHub and runtime revisions must be recorded separately until synchronized; no Workshop release yet.
